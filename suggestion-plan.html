7. Effort rollup & why this order is cheapest

PhaseHands-onReviewWhy this cheapCumulative
P0 baseline15 min—Measure only, no code15 min
P1 prose trim + freeze30 min10 minStrings only, one file45 min
P2 examples + guide30 min10 minREADME only, copy-paste flows1 h 15
P3 CI + keeps15 min10 minOne workflow file + confirm keeps1 h 30

Why this order is the Never-optimize-what-shouldn't-exist order: P0 measures; P1 deletes words that shouldn't exist (long prose); P2 replaces words with examples that teach better in less space; P3 automates only the flows that survived deletion (check + scenario). Reordering P3 before P2 would mean automating flows before the examples that define them — i.e. wiring CI before contributors know the batch-first pattern.

Resourcing. One engineer lands P0→P3 in a single afternoon. With two reviewers, run P1∥P2 to shave ~30 min. No design work remains — suggestion.html is the spec, this file is the schedule. Stop after any green phase; the next phase only adds, never requires a revert.

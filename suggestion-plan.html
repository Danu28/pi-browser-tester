7. Effort rollup & why this order is cheapest

PhaseHands-onReviewWhy this cheapCumulative
P0 baseline15 min—Measure only15 min
P1 waits45 min15 minDeletions, not rewrites; single file1 h 00
P2 vocabulary45 min15 min3 small edits; no tool removed yet1 h 45
P3 surface60 min20 minRewrite only tools[] prose + delete; batch already ready2 h 45
P4 dedupe30 min10 minDelete ~50 lines + 2 smoke blocks3 h 15
P5 hygiene30 min15 minDocs + 3 bat lines; no logic3 h 45

Why this order is the Never-optimize-what-shouldn't-exist order: P1 deletes waits that should not exist; P2 makes the vocabulary singular so P3 has something to collapse into; P3 collapses the surface so P4's dedupe has no surface left to subsidise; P5 touches only packaging. Reordering P3 before P2 would mean deleting tools whose batch replacements don't yet handle scroll/history — i.e. breaking flows to save them.

Resourcing. One engineer can land P0→P5 linearly in an afternoon. With two reviewers, run P1∥P2 to shave ~45 min. No design work remains — design.html is the spec, suggestion.html is the why, this file is the schedule.

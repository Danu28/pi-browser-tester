In one sentence. The extension already has the right architecture (pi-free session.js, batch interpreter, zero-cost scenario replay). The cheapest route to all four goals is not new features — it is collapsing the duplicated vocabulary, deleting the two polling waits, and making cext_batch the single action surface. Everything below is that deletion plus the small ergonomics that make it stick.

The 5-step algorithm, applied to this repo

Rule: Never optimize something that shouldn't exist. Each step is a gate — nothing passes to the next until the previous has had its cut.

1 Question — Challenge every requirement

Ask "does the agent need a dedicated tool for this, or does a batch op already do it?" before touching code.

ClaimChallengeVerdict
14 single-op tools (cext_click, cext_fill …)Every one is already a batch case; cext_batch exists precisely to avoid N round trips. Why ship the same selector twice?Reject — keep 3 aliases only (snapshot/screenshot/logs), everything else is a batch op.
"Body text on every action" + diff layerAgents assert via eval returning the 5 values they care about (README pattern). Diff output still ships bulk text and is stateless-unfriendly.Reject — actions return one line; body text only via cext_snapshot / batch(snapshot:true).
Scan live chrome-extension:// targets to find the IDChromium's ID is deterministic from the path (or key) — already proven by known-answer vectors in smoke.mjs.Reject scanning — compute it.
cext_reload via chrome.runtime.reload() + 4 s pollSide-loaded extensions never respawn their worker; the fallback is always the path.Reject polling — relaunch directly.
Root + folder package.json both declare depsinstall.bat copies — nothing is installed in the extension folder; global playwright is the real dep.Keep but clarify (private wrapper vs manifest).

2 Delete — Remove anything unnecessary

Deletion beats optimization by the full cost of what was deleted.

  • 13 standalone action tools → deleted as tools (kept as batch ops) — ~350 lines, ~5k prompt chars gone. F1
  • changedLinesOnly + _lastBody* + dedupe flag + per-op snapshot option → delete; actions stateless, one line each. F6 F7
  • _scanExtId + 50×200 ms poll (10 s) + _extensionAlive + 4 s reload poll → delete; replaced by computation + relaunch. F4 F5
  • Duplicate param prose (120 lines) + duplicate formatter (batchLine vs scenario.mjs) → delete, derive from single source. F3 F8
  • Two version: "0.5.0" declarations → root becomes private wrapper (no version to bump in two places). F10

What stays: cext_launch, cext_reload (now = relaunch), cext_popup, cext_serve, cext_batch, aliases cext_snapshot/cext_screenshot/cext_logs, cext_cdp, cext_close — 10 tools, one vocabulary.

3 Simplify — Optimize what remains

  • Single OPS list exported from session.js — schema, error message, and scenario.mjs all read it; adding an op = 1 line + 1 case. F2
  • pick([…]) derives alias schemas from batchStep — one description per field, everywhere. F3
  • stepLine() exported from session.js — pi and the scenario runner share one formatter. F8
  • _ctx() + MAX_TEXT — one guard, one cap, not six if (!this.context) copies and two magic 12000s. F13
  • manifest cached on launch — popup() reads the cache, not the disk again.
  • _act → _result — one layer (url + title); no body-text pipeline, no snapshot flag threaded through 8 methods.

No new caching, no prefetching — just stop waiting for things that never happen and stop shipping text nobody asked for.

5 Automate — Only after the above

Automate only the flows that survived deletion:

  • scenarios/*.json already is the automation: node browser-tester/scripts/scenario.mjs dummy-form.json replays with 0 model calls — wire it into CI as npm run scenario after npm run check.
  • install.bat staleness hint — xcopy /L /D prints [install] STALE — re-run install.bat for files newer than the copy; next step would be a mklink /J junction (opt-in, needs Developer Mode).
  • Do not automate ID scanning, diff upkeep, per-tool prose syncing — they are deleted features; automating them would re-create the cost.

Agent-friendly — what to change

Agents pay per tool description and per round trip. Ergonomics = fewer tools, one vocabulary, one-line results, and assertions the model can write.

One vocabulary, one interpreter

  • Keep 10 tools, collapse 13. Every page action is a cext_batch op; cext_snapshot/cext_screenshot/cext_logs stay as 1-line aliases (humans ask for them by name).
  • Publish OPS once (session.js export) — schema + error message + scenario runner read it; adding drag/screenshot-clip/etc is 1 name + 1 case.
  • scroll + history belong in batch (they are missing today, so those flows break out and pay an extra turn).

Results the model can use

  • Actions → one line (3 fill #pass — ok) + final url/title. Body text only via cext_snapshot or batch(snapshot:true) — reduces noise and prevents "page changed? did the body change?" guessing.
  • Eval as assertion: end a batch with {op:"eval", expression:"(async ()=>{ /* read 5 values, throw if wrong */ })()"} — README pattern, no extra tool needed; thrown error = failed step with index.
  • Single stepLine() — same i op selector → result line in pi and in scenario.mjs; no drift.
  • Actionable errors: unknown batch op: scroll (have click/fill/…) names the valid set; NotLaunchedError says "call cext_launch first" — not a raw stack.

Prompt cost paid before the first step runs

Every description + snippet ships in every prompt. Today: 23 snippets (985 chars) + 61 descriptions (6,481 chars) = ~7.5k chars (~1.9k tokens) even before the agent clicks anything. Target: 10 tools, pick()-derived prose, ~2.5k chars (~0.6k tokens) — −⅔, every turn, for free. cost

User-friendly — what to change

First 5 minutes must work

  • Auto-install already works — keep it: first cext_launch installs playwright globally and Chromium (~170 MB) with a 600 s timeout. Don't regress this.
  • Install feedback — install.bat already says what it copied; add the xcopy /L /D STALE warning so "I edited but nothing happened" is impossible.
  • Keep README.md's mirror hint (PLAYWRIGHT_DOWNLOAD_HOST) and the troubleshooting section — the most common failure is a blocked CDN.
  • .pi/extensions/browser-tester is a copy → tell the user. Either the staleness warning or an opt-in junction; silent staleness has burned this repo twice.

Day-to-day ergonomics

  • Keep the three named aliases even though they are batch aliases — humans expect screenshot and logs as verbs. One line each, no duplication.
  • screenshot inline:false by default — path only; large base64 PNGs round-tripped through context are the most expensive "just in case" cost. Opt-in inline:true when the model needs to see it.
  • logs cursor stays in content (must — only content reaches the model, details.next is invisible). Printed as next: 42 — pass as {since} so tailing doesn't re-ship 5000 lines.
  • Artifacts discoverability — every screenshot/download path is under ./artifacts/ (cwd-relative), so the user knows where to look without guessing.

Cost-efficient — what to change

Three bills: prompt tokens (tool prose every turn), output tokens (body text / eval JSON / screenshots per step), and time × polling waits.

What not to "save": don't truncate error messages or log entries to save tokens — the saving is pennies, the cost is a blind agent. Keep MAX_TEXT = 12000 as the cap and let eval return the 5 asserted values compactly.

High-productivity — what to change

Zero-cost replay

  • scenarios/*.json + scenario.mjs replays without a model — already correct; keep the format byte-compatible so existing scenarios survive the tool collapse.
  • Recommended CI: npm run check (no browser, catches ID math + hooks) then npm run scenario -- scenarios/*.json (browser, catches pages). Both exit non-zero with the failing step index.
  • Record, don't automate discovery: use cext_* to find selectors once, then freeze the flow as a scenario — re-exploring is two batch calls, replay is free.

Fast, safe extension loop

  • Edit → cext_reload (now instant relaunch) — no 4 s wait, no "did the worker respawn?" question. install.bat + /reload before live checks.
  • npm run check without pi or a browser — keeps session.js pi-free so pure logic is provable unconditionally. Don't move pi imports into it.
  • cext_serve for content scripts — keep; file:// never runs them, and a 10-line static server is the only workaround.
  • cext_cdp escape hatch — keep; the cost of keeping it is one tool description, the cost of removing it is re-adding a tool the hour permissions/N/W emulation is needed.

Appendix — cost math (so the savings are checkable)

Prompt cost (every turn, even before the first click):

  23 tools × (names+descriptions+snippets) = 6,481 + 985 = 7,466 chars
  10 tools × (names+descriptions+snippets) ≈ 2,500 chars          (−66%)

  At claude-3.5-ish tokenisation (~3.9 chars/token):  7,466 → 1.9k tokens
                                                     2,500 → 0.64k tokens
  Saving per turn: ~1.3k input tokens. Over a 20-turn flow: ~26k tokens.

Output cost (the body-text tax):

  12-step flow today: ~12 bodies × 600–12,000 chars + 12 one-liners
  12-step flow after: 12 one-liners + 1 eval JSON (compact) + optional 1 snapshot
  Typical measured saving on dummy-form: ~90% fewer output chars.

  Screenshot tax (when inline:true): 800×600 PNG ~ 300–800k chars base64
  → default inline:false ships ~40 chars ("screenshot saved: artifacts/...png")
     and lets the agent decide when the image is worth the tokens.

Wall-clock:

  launch(popup-only ext):  10,000 ms →   <1 ms   (−10,000 ms)
  cext_reload:              4,000 ms →     0 ms   (−4,000 ms)
  12-step round trips:     12 turns  →   1 turn  (−11 LLM turns + latency)

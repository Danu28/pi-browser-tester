Agent-friendly — what to change

Agents pay per description char and per round trip. Ergonomics = fewer tools, one vocabulary, one-line results, and assertions the model can already write.

One vocabulary, one interpreter ✔ done

  • 10 tools frozen. Every page action is a cext_batch op; cext_snapshot/cext_screenshot/cext_logs stay as 1-line aliases (humans ask for them by name). Budget: new tool → delete one.
  • OPS single-sourced — schema + error + scenario runner read it; adding an op = 1 name + 1 case.
  • scroll + history in batch — unblocked infinite-list and back-nav flows ✔
  • Next: shorten prose (S-01) — move teaching from descriptions into 3 README batch examples + batch promptGuidelines. Same clarity, 1.4k fewer chars.

Results the model can use ✔ done

  • Actions → one line + final url/title. Body only via cext_snapshot / batch(snapshot:true).
  • Eval as assertion: {op:"eval", expression:"(async ()=>{ /* read 5 values, throw if wrong */ })()"} — thrown error = failed step with index.
  • stepLine() shared — same line in pi and scenario.mjs.
  • Actionable errors: unknown batch op: scroll (have click/fill/…) lists the valid set.
  • Next: selector resilience — document the stable-selector pattern ([type='email'] not #shub39) as the first troubleshooting line; agents fail on randomized ids otherwise.

Prompt cost: what remains

Every description + snippet ships in every prompt. Achieved: 23 → 10 tools, ~7.5k → ~3.9k chars (−48%). Remaining: ~3.9k → ≤2.5k (−36%) by trimming each tool to one crisp sentence and keeping the teaching in batch guidelines + README. At ~3.9 chars/token that is ~0.36k more tokens saved per turn, for the whole conversation. cost

Saving:   ~1,424 chars → ~0.36k tokens / turn × 20 turns ≈ 7.2k tokens / flow

  • Auto-install kept — first cext_launch installs playwright globally + Chromium (~170 MB, 600 s timeout).
  • Install feedback — install.bat says what it copied + xcopy /L /D STALE warning so "I edited but nothing happened" is impossible. ✔
  • README mirror hint (PLAYWRIGHT_DOWNLOAD_HOST) + troubleshooting — keep; most common failure is blocked CDN.
  • Junction alternative documented as opt-in comment (needs Developer Mode) — not default, safe.
  • Next polish: surface the 3 batch examples above the tools table — new users copy-paste before they read prose.

Day-to-day ergonomics ✔ done

  • Three aliases kept — humans expect screenshot and logs as verbs.
  • screenshot inline:false default — path only; large base64 PNGs are the most expensive "just in case" cost. Opt-in inline:true.
  • logs next cursor in content — only content reaches the model, so printed as next: 42 — pass as {since}.
  • Artifacts discoverability — every path under ./artifacts/ (cwd-relative).
  • Next: add artifacts/ prune note (keep last N or 7 days) — unbounded screenshots fill disks in CI.

What not to build — the horizon that fails the ladder

Tempting but skip

  • DOM-outline / accessibility snapshot tool — eval already returns any DOM slice; new tool = second name for same op. Document the pattern instead.
  • Visual regression / image diff — heavy deps (pixelmatch, canvas) for a need screenshot(path) + external diff already covers.
  • Config file / options UI — zero-config is a feature; every option is a line to docs, test, and migrate.
  • Per-tool retry / auto-heal — hides flaky selectors; fix the selector, don't retry it.
  • Framework wrappers (Page Objects, fixtures) — scenarios/*.json already is the harness; frameworks add a DSL to learn.

When to revisit

  • DOM helper → when 3+ agents independently write the same 4-line eval to outline the page — then 1 batch op outline may earn its prose.
  • Config → when a single value actually varies per project (not "might vary").
  • Visual diff → when screenshot comparison becomes a weekly task, not a one-off.
  • New dependency → when stdlib + playwright cannot do it in ≤10 lines. Show the 10-line attempt first.

Rule: deletion over addition, boring over clever. The shortest working diff wins — but only after reading the code it touches.
